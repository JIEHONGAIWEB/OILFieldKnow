## 背景

Model Management 负责管理井的 Well Model(Prosper / GAP / PipeSim / OLGA 等)的上传、版本、校准状态与关联关系。
当前用户完成一次模型相关操作(上传模型、查看校准状态、发起校准、查询某井模型是否可用)需要在多个页面间切换,且需要理解页面字段含义(如 Calibration Status、KPI Status)。

希望引入 **Model Management Agent**:用户用自然语言提问或下达指令,Agent 调用现有 Model Management 接口完成查询与操作,并在写操作前请求用户确认。

## 目标

- 用自然语言完成常见的模型查询与模型操作,减少页面切换。
- Agent 只调用**已有 API**,不新建一套业务逻辑。
- 所有写操作必须经用户明确确认后才执行。
- 对无法确定的信息(井名、模型名、版本)主动追问或给出候选,不做猜测。

## 非目标(本期不做)

- 对现场设备或控制系统的实时闭环控制。
- 修改模型校准算法或物理计算逻辑。
- 自动删除模型或自动覆盖已有校准结果。
- 跨项目、跨资产的模型批量治理(后续版本再评估)。

## 用户角色

| 角色 | 描述 | 典型诉求 |
| --- | --- | --- |
| 生产工程师 | 负责单井或一组井的生产优化 | 查某井模型状态、上传新模型、发起校准 |
| 模型工程师 | 负责模型质量与版本管理 | 查看 KPI 趋势、比较模型版本、审核校准结果 |

## 用户故事

- As a 生产工程师, I want to 用一句话询问某口井当前模型的校准状态, so that 不必逐页查找 Calibration Status。
- As a 生产工程师, I want to 拖拽 Prosper 模型文件到对话框, so that 系统自动识别类型并完成上传。
- As a 模型工程师, I want to 让 Agent 列出某井的历史模型版本及 KPI, so that 快速判断哪个版本可用。
- As a 模型工程师, I want to 在发起校准前看到将要执行的参数摘要并确认, so that 避免误操作覆盖已有结果。

## 功能需求

### FR-1 查询模型信息

- 支持按井名/井号、模型名查询:模型类型、版本、校准状态(`modelCalibrationStatus`)、KPI 状态(`kpiStatus`)、最近更新时间。
- 同名或模糊匹配时返回候选列表,由用户选择。

### FR-2 上传模型

- 支持拖拽或选择文件上传;系统根据扩展名与内容识别模型类型。
- 不支持的格式直接拒绝,并说明支持的格式列表。
- 上传成功后返回模型摘要(名称、类型、关联井)及上传结果;失败时返回原因。

### FR-3 发起校准(写操作)

- Agent 解析目标井、模型版本、校准范围,生成**校准配置草稿**。
- 草稿展示给用户,用户确认或修改后才提交。
- 提交后返回任务 ID,并在对话中回传进度与结果摘要。

### FR-4 Agent 工具契约

Agent 仅通过以下工具调用后端,每个工具对应一个现有接口(接口清单待后端确认):

| 工具 | 类型 | 说明 | 需要确认 |
| --- | --- | --- | --- |
| `search_well_model` | 读 | 按井/模型名查询模型列表 | 否 |
| `get_model_detail` | 读 | 获取单个模型的校准状态与 KPI | 否 |
| `upload_model` | 写 | 上传模型文件 | 是(覆盖同名模型时) |
| `start_calibration` | 写 | 发起模型校准 | 是(始终) |
| `get_task_status` | 读 | 查询校准任务进度与结果 | 否 |

### FR-5 缺失信息处理

- 写操作缺少必填参数(井、模型版本、校准范围)时,Agent 追问,不得使用默认值替代。
- 默认值仅允许用于非关键参数,且必须在草稿中显式展示。

## 交互流程示例

```
用户: 把 Well-0032 的 Prosper 模型重新校准一下
Agent: 找到模型 Well-0032_Prosper_v3(当前 Calibration Status: Rejected)。
       请确认校准配置:
         - 井: Well-0032
         - 模型版本: v3
         - 校准范围: 2026-10-01 ~ 2026-11-10
         - 参数: 默认
       [确认提交] [修改] [取消]
用户: [确认提交]
Agent: 已创建校准任务 CAL-20261111-0007,状态: Running。
...
Agent: 任务完成: Calibration Status 更新为 Approved,KPI 状态: Good。
```

## 验收标准

- [ ] 输入井名或模型名后,返回模型类型、版本、校准状态、KPI 状态。
- [ ] 模糊匹配时返回候选列表,用户未选择前不执行后续操作。
- [ ] 拖拽支持的模型文件可完成上传,并返回摘要与成功/失败状态。
- [ ] 不支持的文件格式被拒绝,并提示支持的格式。
- [ ] `start_calibration` 与覆盖式 `upload_model` 在用户确认前**不发起任何后端写请求**(可通过后端日志验证)。
- [ ] 缺少必填参数时 Agent 主动追问,不使用猜测值。
- [ ] 每次写操作记录操作人、时间、参数与结果,可在审计日志中查询。
- [ ] Agent 以当前登录用户的权限调用接口;无权限时返回明确提示,不尝试绕过。
- [ ] 校准任务结束后,对话中回传结果,并包含任务 ID 以便回溯。

## 非功能需求

- **响应时间**:读操作首字节响应 ≤ 3 s;写操作确认后的任务创建 ≤ 5 s(不含后台校准执行时间)。
- **安全**:不在对话或日志中输出凭证;文件仅通过既有上传接口传输。
- **可用性**:Agent 不可用时,页面原有功能不受影响(Agent 为增量入口)。
- **可观测性**:记录每次工具调用的名称、耗时、成功/失败。

## 关键设计考量

- **Human-in-the-loop**:所有写操作必须经用户确认,确认前不调用写接口。
- **复用现有 API**:工具层薄封装,业务规则留在后端。
- **歧义处理**:名称模糊时给出候选,不自动选择。
- **权限与审计**:沿用当前用户权限;写操作全量审计。
- **边界**:Agent 驱动的是模型管理与校准任务,不是实时控制。

## 开放问题

1. Chatbox 承载位置:全局悬浮还是 Model Management 页面内嵌?
2. 后端是否已有可直接复用的上传、校准、任务状态接口?接口清单与鉴权方式待确认。
3. "覆盖同名模型"的业务定义是什么,是否需要保留历史版本?
4. 校准任务的最长耗时与超时后的处理方式?
5. Agent 后端选型(自建编排 / 现有平台能力)?

## 超出范围

- 对现场控制系统/设备的实时闭环控制。
- Model 本身的校准算法改动。
- 跨资产的模型批量治理。
