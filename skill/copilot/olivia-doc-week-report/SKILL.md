# Weekly Report From Docs

从项目里最近的功能实现文档中提取信息，生成一份给团队/管理层看的周报。**不假设固定路径**——先动态定位 docs 目录，再处理。

## 前提假设（如与实际不符，先跟用户确认一次即可，之后按确认结果执行）

- `docs` 文件夹里每个功能对应一个或一组 Markdown 文件（例如 `feature-xxx.md`、`YYYY-MM-DD-xxx.md`，或按子文件夹组织）
- "最近 7 个"默认按**文件最后修改时间**排序取前 7 个；如果文件名/frontmatter 里有明确日期，优先用日期排序而非文件系统 mtime
- 如果同一个功能拆成多个文件（比如设计文档 + 实现记录），按功能合并计数，不要把同一功能的多个文件当成 7 个不同条目

如果扫描后发现日期信息缺失或排序方式有歧义，向用户确认一次排序依据，不要静默假设。

## 执行步骤

### 第 0 步：动态定位 docs 目录

不要硬编码任何项目名或路径。先在当前工作目录（以及必要时向上/向下一层）搜索名为 `docs` 的目录：

```bash
# 在当前目录及子目录中查找名为 docs 的文件夹，最多向下搜 3 层，避免扫到 node_modules 等无关目录
find . -maxdepth 3 -type d -iname "docs" -not -path "*/node_modules/*" -not -path "*/.git/*"
```

处理结果：

- **只找到 1 个**：直接使用这个目录，继续下一步
- **找到多个**：列出所有候选路径，向用户确认用哪一个（不要自行猜测选第一个）
- **一个都没找到**：向上一层目录（`find .. -maxdepth 2 ...`）再搜一次；如果仍然没有，明确告诉用户"当前目录下未找到 docs 文件夹"，并询问实际路径，不要臆造一个路径继续往下走
- 如果用户在请求里已经明确给了路径（比如粘贴了具体路径），直接用用户给的路径，跳过搜索

### 第 1 步：在确定的 docs 目录下定位并排序文档

假设上一步确定的目录变量为 `$DOCS_DIR`：

```bash
# 按修改时间排序，找最近的文件
find "$DOCS_DIR" -name "*.md" -printf '%T@ %p\n' | sort -rn | head -20
```

如果文件名或 frontmatter 包含日期字段（如 `date:`、`updated:`），优先解析这个字段排序，而不是纯用文件系统时间（文件系统时间可能因为 git clone/pull 被重置）。

去重合并同一功能的多个文件后，取最近 7 个功能。

### 第 2 步：逐个提取关键信息

对每个功能文档，提取：

- **功能名称**（标题或文件名）
- **完成/更新时间**
- **一句话描述**：这个功能解决什么问题（如果文档没有直接写，从"背景/目的"类段落提炼，不要编造）
- **涉及模块/文件范围**：文档里提到的改动范围（前端/后端/数据库/接口等）
- **状态**：已完成 / 测试中 / 部分完成（从文档措辞判断，如果文档没写明确状态，标注"状态未注明"，不要猜测）
- **关联信息**：如果文档提到了 PR 链接、issue 编号、负责人，一并记录

如果某个文档信息不全（比如没写状态），在报告里如实标注"未注明"，不要为了让报告好看而编造内容。

### 第 3 步：生成周报

用以下结构输出（默认在对话中直接输出 Markdown；如果用户要求"文件"、"存下来"等，才落地为 `.md` 文件）：

```markdown
# [项目名] 周报（[起止日期]）

## 本周功能概览
共 N 个功能实现/更新，涉及 [模块范围概述]。

## 功能详情

### 1. [功能名称]
- **状态**：[已完成/测试中/未注明]
- **说明**：[一句话描述]
- **涉及范围**：[模块/文件]
- **关联**：[PR/issue 链接，如有]

（按此格式列出全部功能，按时间从新到旧排列）

## 风险与待关注事项
[如果某些文档提到已知问题、待办、阻塞项，汇总在这里；如果没有相关信息，写"本周文档未提及风险项"]

## 下周展望
[仅当文档中明确提到后续计划时填写；没有就省略这一节，不要编造]
```

### 第 4 步：交付前自检

- 报告里的每一条信息都能在原始文档里找到出处，没有编造或过度推测
- 如果 7 个功能里有些文档质量很差（缺状态、缺描述），如实反映"信息不全"，而不是脑补填满
- 如果用户是要给非技术背景的人看（比如老板、产品），主动询问是否需要把"涉及范围"这类技术描述换成更业务化的语言

## 常见变体

- 用户可能只想要"最近 7 天"而非"最近 7 个功能"——如果文档量很大导致"最近 7 个"覆盖时间过短/过长，向用户确认到底是按数量还是按时间窗口筛选
- 用户可能想要英文周报——按用户使用的语言输出，不确定时用中文（因为项目上下文是中文交流）
